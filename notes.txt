Class - 2
==========

    -> Configuration Items (CI's)

        -> Configuration Items are "Atoms Of CMDB"

        -> Configuration Items (CI's) in ServiceNow is a digital record within 
        the CMDB representing "Any Manageable IT Component" such as 
        Server, Application, Network Device, Service etc 

        -> Without CMDB 

            -> https://www.lansweeper.com/wp-content/uploads/2019/06/All-servers-by-type.png

        -> With CMDB (CI's)

            -> https://servicenowguru.com/wp-content/uploads/2024/05/bsmMap.jpg

        -> A CI Has three things 

            -> Class (What Type Of CI it is)

            -> Attributes (Properties)

            -> Relationships (How it connects to Other CI's)

    
    -> Relationships 

        -> A Relationship in servicenow CMDB is a connection between 
        Multiple Configuration Items(CI's) that defines

            -> How they interact with others 

            -> How they Depend on others 

                -> Runs On (An Application Runs On Server)

                -> Used By (A Disk is Used By Server)

                -> Depends On (A Service Depends On an Application)

                -> etc 

    
    -> Discovery 

        -> Process Of Automatically Identifying and Populating
        CI's into the CMDB. 

            -> CMDB (Think of it as City Map)

            -> CI's (Buildings within City - Address, Color)

            -> Relationships (Roads Connecting Buildings)

            -> Discovery (Keeps City Map Updated Automatically)

        -> ServiceNow Discovery is an "Automated Process" that continuously 
        Scans and Identifies All Components Within IT Infrastructure and 
        their Relationships, there by writing all these into CMDB 

        -> NOTE: Discovery Plays Crucial Role for Maintaining Accurate Info IN CMDB 

        -> NOTE: Discovery Is not Available Out of box in PDI, we need to install 
        Discovery Plugin to get "Automated Process" that continuously 
        Scans and Identifies All Components.

    
        -> To Start With Discovery 

            -> Schedules & Triggers 

                -> Admin defines IP Range (Data center address - 10.0.0.0/24) 
                10.0.0.0/24 can hold 250 Servers 

                -> Define Schedules, run on demand (when you need manually) or 
                run automatically daily at mid night or weekly on monday 

            -> Scan Network 

                -> MID Server Probes network using network protocols like 
                SSH, WMI, SNMP, ICMP etc to find devices 

                -> MID Server Scans 

            
            -> Classification & Identification

                -> Probes Collect Hardware, OS, Softwares etc 

                -> Sensors Classify Each Device Type 

            
            -> Populate CMDB    

                -> CI's can be created / updated in CMDB 

                -> Relationships are established 

        -> NOTE: Discovery = Zero Manual Data Entry For Infrastructure CI's



    -> MID Server  

        -> M - Management 

        -> I - Instrumentation 

        -> D - Discovery 

        -> Management: MID Server Manages "Communication" between "Service Now Instance"
        and "Your IT Infrastructure" 

            -> Service Now Instance is running outside your Infrastructure (Azure Cloud)

        
        -> Instrumentation: Reading Pulse Of Every Device In Your Infrastructure 

            -> Just Like Doctors Use Instruments To Check Vitals (BP Machine, Thermometer)

            -> MID Server Probes Hardware, Servers, OS, Database Software etc 

            -> Collects Data Like Hardware Type, OS Type, Installed Applications etc 

        
        -> Discovery: Finds Assets Nobody Manually Told Service Now

            -> MID Servers Scans IP Ranges and Finds Devices Automatically 

            -> No Human Intervention Required 

        
        -> Requirements For MID Server 

            -> MID Server is an Java Application 

            -> Install Java Version 11 or Above 

            -> Corporate Network / Physical Server / Virtual Machine / Cloud VM etc

    -> Discovery

    -> Credentials 

        -> Once the MID Server Reaches Your Devices, it needs to Login into 
        Devices to interrogate devices, that's where Credentials are required. 

        -> Credentials are Authentication Secrets stored Securely in Service Now, 
        from here MID Server Uses Credentials To Access Devices. 

        -> Credentials are never stored in plain text, they are "Encrypted"

        -> MID Server Receives Encrypted Credentials and Decrypts it at the time of use


        -> We have different types of Credentials based on the Infrastructure needs 

            -> SSH Credentials used in Linux & Unix Environments 
            SSH Credentials are made of Username, Public Key & Private Key. 

            -> Windows Credentials Uses, Regular Username & Password. 

            -> JDBC Credentials For Databases 

            -> VM Ware Credentials 

            -> Cloud Infrastructure Like AWS, Azure etc uses API Keys or Tokens 

            -> etc 

        

    -> Probes & Sensors 

        -> Probes & Sensors are two halves of same job.


    -> Probes

        -> A Probe Is Question 

            -> It's a Script / Command, that MID Server Executes against 
            Target Device to collect RAW Data. 

            -> It Runs On MID Server Side, reaches to Target Device and brings 
            all raw output like Commands, XML, JSON etc 

            -> The Raw Output Will be stored at Service Now inside 
            ECC (External Communication Channel)

        
    -> Sensors 

        -> A Sensor Is Answer 

            -> It's a Script that takes raw output from probe and parses it
            extracting fields like OS, Version, IP Address, Hostname etc 
            and Maps them to CI Attributes, updating records in CMDB.



    -> Detective Story 

        -> Detective Assistant / Probe 

            -> Goes to Crime Scene, Takes Photos, Lifts Fingerprints etc 
            collected all raw evidences. 

            -> ITOM: Probes runs Scripts, Collects Data 

        
        -> Bag Of Evidence / ECC Queue 

            -> Bag Of Evidence Contains Lot Of Unprocessed Raw Evidences 

            -> ITOM: RAW Data is collected into ECC 


        -> Detective / Sensor 

            -> Detective sits at desk, opens the bag of evidences and 
            examines each item, extracts meaning of those items and
            writes the final case report.

            -> ITOM: Extracts Data From ECC Queue and gives meaningful fields 
            like OS, Version, IP Address, Hostname etc 


        
            -> Service Now Says -> "Discover this IP" 

                -> Mid Server Sends Probe -> run scripts on target devices

                    -> Raw Data Drops Into ECC Queue (ecc_queue table)

                        -> Sensor picks up data then reads, parses and extracts 

                            -> CMDB gets updated with new CI record 

    
    -> Patterns 

        -> Patterns are Service Now's Modern Replacement for Older Probes / Sensors 

        -> Patterns are especially used for Software Services Discovery. 

        -> Probes & Sensors are still heavily used for Infrastructure (Hardware / OS / NW) 

        -> Pattern is a Declarative Definition, Unlike Imperative for Probes & Sensors 

            -> Imperative Definition Means "How To Do"

            -> Declarative Definition Means "What To Do"

        -> Patterns are written in Visual Designer(Pattern Designer), 
        rather than raw javascript 



    -> Discovery Schedules 

        -> A Discovery Schedule is Configuration record, that defines a discovery run. 

        -> It Answers:

            -> What should be Scanned 

            -> When To Do Scan 

            -> Which Mid Server To Use For Scanning 


        -> Key Fields Of Discovery Schedule 

            -> IP Ranges To Scan / Individual Address 

            -> Schedule: Daily or Weekly (Automated) or On-Demand (Manually)

            -> MID Server (Name/IP)

        
        -> NOTE: When Schedule Completes, It Creates "Discovery Status" Record 

        -> NOTE: Discovery Logs, within each Status Record is your "Debugging Tool" 

            -> To find root cause issues or why discovery failed 

            -> Shows Which IP was tried, What Probe / Pattern was executed. 
            Which CI is created / updated etc 


    -> CI Classification 

        -> CI Classification is the final step, the "Classifier Engine" 
        determines what CI class to create or Update Existing One 

        -> When Sensor or Pattern, finishes parsing data from device,
        it hands over RAW Attributes to "Classifier Engine" 

        -> The "Classifier Engines" Job is to look at the Attributes and answer 

            -> What Type Of CI is this ?

            -> Does this already exists in CMDB ? 

        -> "Classifier Engines" has Identification Rules 


        -> Identification & Reconciliation 

            -> Identification Rules For Matching Configuration Items Before Insert / Update 

        
        -> IRE (Identification & Reconciliation Engine)

            -> IRE Engine is underlying engine that uses Identifier rules 

            -> Each CI Class has defined set of "Identifier Fields"
            that together makes a CI Unique Using Criterion Attributes. 

            -> Criterion Attributes are Unique Fingerprints Of CI 

            -> For Apache Web Server, its the Combination Of 
            Class Name + Config File + Version is the Identifier 

            -> For Docker Container, the container_id is the Identifier 

            -> etc 

        
        -> IRE - Questions it always asks ? 

            -> What are you ? 

                -> Linux Server / Desktop / Apache Web Server / Container ?? 

            -> Have i seen you before ?

                -> Does this CI already exist in CMDB 

                    -> YES - Update Existing CI 

                    -> NO - CReate New CI
